SECTION 1 - SERVICE DACL / SERVICE-CONTROL PERMISSION ABUSE
================================================================================

TEST #1 - Service DACL / Service-Control Permission Abuse

Purpose: Detect services where low-priv users can change config/start/stop.

CMD:
sc sdshow <service_name>
sc query <service_name>
sc qc <service_name>

SAFE OUTPUT EXAMPLE:
D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)

VULNERABLE OUTPUT EXAMPLE:
D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;RPWPCRCCDCLCLORCWOWDSDDTSW;;;BU)

WHAT TO LOOK FOR:
- ACEs granting CC (Change Config), RP (Start), WP (Stop), WD (Write DAC)
  to BU, IU, AU, WD (Everyone), or other non-admin principals.

WHY IT MATTERS:
- SERVICE_CHANGE_CONFIG allows binary-path redirection.
- Start/stop rights allow triggering the modified binary.

EXPLOITABILITY CONDITIONS:
- Need CC plus ability to restart service (RP/WP or reboot).
- Service account privilege determines impact (SYSTEM = critical).

EVIDENCE:
- sc sdshow, sc qc, sc query output.
- whoami /groups proving low-priv context.

SEVERITY:
- High if CC + RP/WP to Users.
- Critical if service runs as SYSTEM.

SAFE VALIDATION:
- sc query <svc> (read-only).
- Attempt sc config <svc> binpath= ... should return Access Denied.

TEST #2 - Privileged Service Binary ACLs

Purpose: Check ACLs on service executables running as SYSTEM/privileged.

CMD:
sc qc <service_name>
icacls "<binary_path>"

SAFE OUTPUT EXAMPLE:
C:\Program Files\Vendor\svc.exe BUILTIN\Administrators:(F)
                              NT AUTHORITY\SYSTEM:(F)
                              BUILTIN\Users:(RX)

VULNERABLE OUTPUT EXAMPLE:
C:\Program Files\Vendor\svc.exe BUILTIN\Users:(M)
                              BUILTIN\Administrators:(F)
                              NT AUTHORITY\SYSTEM:(F)

WHAT TO LOOK FOR:
- (M), (W), (F), or (D) for BU, AU, WD, or IU on privileged binaries.

WHY IT MATTERS:
- Writable privileged binary = direct privilege escalation.

EXPLOITABILITY CONDITIONS:
- Attacker must be able to modify the binary and trigger service restart.

EVIDENCE:
- sc qc output, icacls output, service account identity.

SEVERITY:
- Critical if SYSTEM service binary is writable.

SAFE VALIDATION:
- accesschk -wvu "<binary_path>" (if available) or icacls review only.

TEST #3 - Service Parent-Directory ACLs

Purpose: Check ACLs on directories containing privileged service binaries.

CMD:
sc qc <service_name>
icacls "<parent_directory>"
icacls "<grandparent_directory>"

SAFE OUTPUT EXAMPLE:
C:\Program Files\Vendor BUILTIN\Administrators:(F)
                       NT AUTHORITY\SYSTEM:(F)
                       BUILTIN\Users:(RX)

VULNERABLE OUTPUT EXAMPLE:
C:\Program Files\Vendor BUILTIN\Users:(OI)(CI)(M)
                       BUILTIN\Administrators:(F)
                       NT AUTHORITY\SYSTEM:(F)

WHAT TO LOOK FOR:
- (W), (M), (F) for BU/AU/WD on any parent directory in the service path.

WHY IT MATTERS:
- Allows DLL planting, config tampering, or binary replacement.

EXPLOITABILITY CONDITIONS:
- Service must load DLLs/config from that directory, or binary must be replaceable.

EVIDENCE:
- icacls on each path component.

SEVERITY:
- High to Critical depending on service account.

SAFE VALIDATION:
- icacls review only; do not create/modify files.

TEST #4 - Unquoted Service Paths with Full Path-Component Analysis

Purpose: Find unquoted service paths with writable intermediate directories.

CMD:
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows\\" | findstr /i /v """
icacls "C:\Program Files\Vuln Service"
icacls "C:\Program Files"
icacls "C:\"

SAFE OUTPUT EXAMPLE:
C:\Program Files\Vuln Service BUILTIN\Administrators:(F)
                         NT AUTHORITY\SYSTEM:(F)
                         BUILTIN\Users:(RX)

VULNERABLE OUTPUT EXAMPLE:
C:\Program Files\Vuln Service BUILTIN\Users:(OI)(CI)(M)

WHAT TO LOOK FOR:
- Unquoted path with spaces AND a writable intermediate directory.

WHY IT MATTERS:
- Windows resolves the shorter path first; attacker places malicious exe.

EXPLOITABILITY CONDITIONS:
- Must be able to write to a preceding path component AND trigger execution.

EVIDENCE:
- wmic output, sc qc (BINARY_PATH_NAME), icacls on each component.

SEVERITY:
- High to Critical (SYSTEM = Critical).

SAFE VALIDATION:
- Create and delete a harmless test file in the writable dir (with approval).

TEST #9 - Image File Execution Options (IFEO)

Purpose: Detect debugger hijacking of executables.

CMD:
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options" /s

SAFE OUTPUT EXAMPLE:
(no Debugger values present)

VULNERABLE OUTPUT EXAMPLE:
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\sethc.exe
    Debugger    REG_SZ    C:\Windows\System32\cmd.exe

WHAT TO LOOK FOR:
- Any Debugger REG_SZ value, especially for sethc.exe, utilman.exe, osk.exe, Magnify.exe.

WHY IT MATTERS:
- Debugger runs in place of target binary; accessibility binaries run as SYSTEM at lock screen.

EXPLOITABILITY CONDITIONS:
- Requires write to HKLM IFEO (admin/SYSTEM) or exploitation of a writer.

EVIDENCE:
- reg query /s output.

SEVERITY:
- Critical for accessibility binaries; High for persistence.

SAFE VALIDATION:
- reg query only.

EVIDENCE:

SEVERITY:
- Medium to Critical.

TEST #23 - Sensitive Windows User-Right Assignments

Purpose: Detect dangerous user-right grants.

CMD:
secedit /export /cfg %TEMP%\secpol.inf
type %TEMP%\secpol.inf | findstr /i "SeDebugPrivilege SeBackupPrivilege SeRestorePrivilege SeTakeOwnershipPrivilege SeImpersonatePrivilege SeAssignPrimaryTokenPrivilege SeLoadDriverPrivilege"

SAFE OUTPUT EXAMPLE:
SeDebugPrivilege = *S-1-5-32-544
SeImpersonatePrivilege = *S-1-5-32-544,*S-1-5-18,*S-1-5-19,*S-1-5-20

VULNERABLE OUTPUT EXAMPLE:
SeDebugPrivilege = *S-1-5-32-544,*S-1-5-32-545
(Users granted SeDebugPrivilege)

WHAT TO LOOK FOR:
- BU (S-1-5-32-545), AU (S-1-5-11), or WD (S-1-1-0) in sensitive privileges.

WHY IT MATTERS:
- SeDebugPrivilege = LSASS access; SeImpersonate = token theft; SeBackup/Restore = file read/write bypass.

EXPLOITABILITY CONDITIONS:
- Depends on privilege; often immediate escalation.

EVIDENCE:
- secpol.inf export and relevant lines.

SEVERITY:
- High to Critical.

SAFE VALIDATION:
- secedit /export only (does not modify).

ADVANCED WINDOWS ATTACK-PATH CORRELATION
================================================================================

EXAMPLE 1 - Service Binary Hijack to SYSTEM
Privileged service (LocalSystem)
  -> sc qc shows unquoted BINARY_PATH_NAME with spaces
  -> icacls shows writable intermediate directory for BU/AU
  -> low-priv user places malicious exe in intermediate dir
  -> service restart (reboot/dependency/failure action)
  -> Windows resolves shorter path first
  -> attacker exe executes as NT AUTHORITY\SYSTEM

EXAMPLE 2 - COM Hijack to Privileged Process
Privileged process (SYSTEM/admin) loads CLSID {X}
  -> Procmon shows HKCU\...\CLSID\{X}\InprocServer32 = NAME NOT FOUND
  -> attacker creates HKCU key + malicious DLL
  -> privileged process instantiates CLSID again
  -> Windows loads HKCU DLL (priority over HKLM)
  -> attacker DLL executes in privileged process

EXAMPLE 3 - Weak Service DACL + Failure Action
sc sdshow shows BU with CC/RP/WP
  -> sc qfailure shows COMMAND_LINE pointing to writable path
  -> attacker modifies binpath or failure command
  -> triggers service failure/restart
  -> payload executes as service account (SYSTEM)

EXAMPLE 4 - IIS AppPool + Writable Webroot
appcmd shows pool identity = LocalSystem or privileged user
  -> icacls webroot shows BU with (M)
  -> attacker uploads web shell
  -> code executes in IIS worker process as privileged identity
